# 秦朗的工作偏好（长期有效，持续补充）

## 协作方式
- **先审脚本，再动手。** 脚本 / 分镜在飞书审定之前不剪、不渲染、不生成。用户说“先不要剪 / 不要执行”时，只做方案与经验沉淀。
- **执行力拉满，绝不偷懒缩水。** 长片建议按章节拆分为独立子工程分段精制（让算力与注意力集中在每一章的每个镜头上），最后用整数采样锁定的全局母带与光学丝滑转场合成全片；每做完一步必须亲自抽帧看画面、跑客观指标核验，严禁只看命令返回 `0` 就交差。
- **要高效且擅用多工具协同。** 不主动安排补拍；家常画面、通用场景先从网上找无字幕干净素材，缺定制静态图/剖面图/垫图主动调用 **Nano Banana / Imagen（`image-generator`）** 生成现代商业风参考图，复杂信号/数据机制主动写 **Canvas / SVG 代码动效**，比喻与情绪动态镜头再用 **LibTV `magi-2`**。
- **拍板项只问 2–3 个真正影响结果的问题**，其余给结论；用户回答后立即写进本技能，下次直接按默认执行、不再重复问。
- **每轮实战双交付**：既把当期成片打磨到位，也同步把新沉淀的硬标准更新进本地全局技能目录与 GitHub 开源仓库，确保换任何新线程做下一期片子都不会退回旧版。
