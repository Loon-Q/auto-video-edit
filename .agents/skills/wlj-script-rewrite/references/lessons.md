# 失败教训（被用户否定过的做法）

来源：《AI 对话玩具》V0.4 脚本与 V4 成片（2026-11-24 至 11-26），用户结论“画面对不上、像 PPT、节奏和音乐都不喜欢”。

| 做法 | 用户反馈 / 问题 | 以后怎么做 |
|-|-|-|
| 用文字卡、AI 图顶替实物 | 说到玩偶看不到玩偶，背景看不出是什么 | 每句先问“观众该看到什么实物”，能拍就拍、有史料用史料 |
| 每段发明一种版式（胶囊、圆窗、目录、画框、角标） | 像 PPT；左上小字不应该出现 | 全片只用 3 种画面状态 |
| 照抄旧脚本的画面描述 | 脚本侧的画面本身就有问题 | 旧脚本画面只当线索，按实际素材重写 |
| 台词照单全收 | 废话多、同一件事讲两遍 | 先出删减方案，再写分镜 |
| 开场用 74 BPM 慢歌 | 开场不抓人 | 开场 ≥110 BPM，每章一首 |
| 字号偏小、句子偏长 | 肉眼看不完 | 关键词 ≤6 字、≥120px，说到才出 |
| B-roll 带原字幕 / 水印 | 与自家字幕重叠 | 逐条检查，带字幕的弃用或裁掉 |
| 镜头间插入不同画面造成跳帧闪帧 | “这种细节绝对不能出现” | 视频 `data-start` 不早于淡入；未出场层默认 opacity 0；交付前逐帧查剪口 |
| 删减后残留口误重复（如“摇手柄划过蜡，摇手柄划过蜡筒”） | 剪辑错误 | 纯口播版先给用户听，再进包装 |
| 赶工交付全片再逐条返修 | 用户被迫逐帧挑错，怀疑执行力 | 先交脚本审定 → 再交冷开场 + 第一章样片 → 定手感后做全片 |
