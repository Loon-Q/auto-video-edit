# 秦朗的工作偏好（长期有效，持续补充）

## 协作方式
- **先审脚本，再动手。** 脚本 / 分镜在飞书审定之前不剪、不渲染、不生成。用户说“先不要剪 / 不要执行”时，只做方案与经验沉淀。
- **要高效。** 不主动安排补拍；家常画面、通用场景先从网上找（官方产品片、公开视频、素材站），再考虑代码画布，最后才是 LibTV。
- **拍板项只问 2–3 个真正影响结果的问题**，其余给结论；用户回答后立即写进本技能，下次直接按默认执行、不再重复问。
- 用户分享的方法（如张亮转来的 guizang-magi2-skill）要先学会、装好、验证能用，再把适用场景写进流程。
- 用户希望通过对话完成两件事：**这一期脚本落实** + **把经验沉淀进技能包**。每轮对话结束前检查有没有新经验要补。
